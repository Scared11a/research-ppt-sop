# 面向听众的成品审阅

收到纠正后交付更新后的完整成品。把同类问题清理到标题、正文、图内字、图注/表格、页脚、讲者备注，以及继承页和新增页；不能只改用户点名的一处，也不以新增说明文档代替PPT修订。先写清楚再交付，常规自检过程不进入面向用户的汇报。

## 按语义分配内容

| 内容 | 成品怎样表达 | 记录位置 |
|---|---|---|
| 研究问题/任务 | 观众应理解的对象、输入与能力要求 | 主画面/讲述 |
| 方法图/公式 | 具体输入、运算、条件、输出或作用位置 | 主画面/必要技术备注 |
| 数值/像素/负结果 | 比较对象、指标/单位/分母、观察与可支持含义 | 主画面/必要条件备注 |
| 来源 | 正式作者、方法/论文、年份/图号及必要版本 | 学术引用/技术出处 |
| 制作、权限、用户指令、工具与核验过程 | 谁提供截图、等谁回复、哪个工具跑过、要求保留什么 | 制作日志/交付报告，不进面向老师的内容 |

讲者备注仍是科研讲述的一部分。它可承载转场、定义、详细条件和来源，不接收正文删下来的整段制作话术。

## 实际审阅步骤

1. 从最终PPTX按实际页序读取全部文字与备注，覆盖继承/新增页。`assets/audience-review.csv`记录候选、所在面、对应来源、实际对象/条件、处理与替换后句子。
2. 检索“用户提供截图”“作者整体方法图”“原图注保留”“先看主图”“待接回执”“旧图册/旧reader”等仅用于发现候选。逐处读本页、关联图/数表、备注和相邻转场，不能按词表自动删除。
3. 判断候选承担的是研究信息、必要条件/来源，还是制作过程。保留前两类并写具体；制作过程移到制作日志，空洞指令删除。不能把实验限制一并抹掉。
4. 用具体内容重写，核标题的证据强度与图/表一致。已有像素对照只说明可观察差异，不能单独标题宣称稳定收益、总体改善或机制成立。
5. 回读更新后的最终文件，检查同义残留与原数字/单位/来源、负结果是否完整。交付更新成品与真正遗留，不把自检过程变成正文。

## 修订示例与理由

### 方法页：用计算内容命名

原句：`Method-A：作者整体方法图`。

“作者”“整体图”只说素材身份，未解释方法。原文已核两观测方位参考及其约束作用时，可改为：`Method-A：双观测方位参考约束目标方位生成`，正文再写清参考、约束与生成之间的实际关系，并保留正式引用。

如果相应机制尚未核实，采用中性且有已核依据的题名，如`Method-A：方位条件与生成路径`；不能为去掉制作话术而补造机制事实。图源身份进来源记录，不写“用户提供截图、原图注保留”。

### 结果页：把读出对象与评价范围写实

原句：`旧图册使用旧reader，已有新评估`。

先查是否有同一批样本的新逐图结果、哪些任务被重评、具体方法/窗口/指标/分母是什么。若新增的只有类别总体一致性，没有新的方位逐图预测，就分开表达：

- `类别一致性：以〔已核分类方法〕在〔评价集合，n=…〕统计请求类别匹配率。`
- `方位预测：本页数值由〔已核方位方法/训练与窗口条件〕产生；本批尚无更新的逐图方位预测。`

必须填入真实方法和条件，方括号只供制作源填写，不能留到成品。不能暗示类别重评同步更新了方位图册，也不能把类别方法写成方位方法。若真有同批新旧读出比较，在同页明确两种方法/条件、相同样本与实际差异；无比较则不空喊“新/旧”。

### 图证页：标题与证据匹配

只有按请求匹配的像素：将`方法显著提升控制能力`改成`固定请求下的生成样例与实测参照`，并交代固定/改变条件与参照身份。总体收益由对应统计与协议决定，不能由样例数量代替。

只有边界内侧改善、外侧代价：把两侧指标与解释一起保留，可得完整负结果；不强改成肯定结论。

### 来源与条件不是制作语言

`Author et al., 方法名, 年份, Fig.2`是正式来源，应保留。`真实Dev参照同图复用`若影响比较身份，应就近写明；`某窗口下的预测结果`若影响指标解释，也应保留。它们不因出现“版本/参照/方法”就被误删。

`assets/revision-examples.json`保存可独立审读的通用例子，不含私人研究数值；样例回归检查语义和来源要求，不以清除禁词当作成品通过。
