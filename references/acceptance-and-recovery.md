# 验收与异常处理

## 四层分别记录

| 层 | 检查对象 | 可以报告什么 | 不能替代什么 |
|---|---|---|---|
| 结构 | 最终PPTX页序、关系、部件、对象类型 | 文件结构/所列对象通过 | 科学正确、视觉、GUI编辑 |
| 内容 | 正文/图内字/公式/数表/图表数据/备注与来源 | 指定内容和数据保持或已修正 | 视觉可读、Office显示 |
| 设计 | 主图及整页同源预览、原参考并排 | 所看预览的比例、层级与阅读路径 | 从PPTX实际渲染、字体运行时生效 |
| Office/行为 | 最终PPTX在指定应用打开/导出/编辑 | 该应用与动作覆盖内通过 | 未测平台或未测交互 |

## 实际文件检查

1. 从`presentation.xml`的`sldIdLst`经关系取得实际页序，不以slide文件名排序代替。
2. 对要求原生的对象检查唯一名称、真实类型、文字/runs内容；仅对象存在或数量很多不足以通过。组变换、翻转/旋转需考虑，不确定边界单独标明。
3. 按[封面目录规范](cover-and-navigation.md)核对封面整页构图/题名/署名机构层级，目录实际章节及范围、主讲/备查数量、旧→新映射、跳转目标、页内导航与正文/备注引用；覆盖继承页和新增页。
4. 公式变量、上下标、乘加/融合位置、训练/推理、数表值和单位与主稿/来源逐项相符。删除重复文案不能删除有效技术依据。
5. 图表从页面`c:chart/@r:id`进入页面关系，再进chart及工作簿关系；导入可位于`full_import/...`。备注从notesSlide关系取得，不能假定同编号。必要图表/媒体引用缺失应报错。
6. 增量编辑对比相应旧版本：声明修改的部位确实改变，其他对象/数据/关系按任务保留。无需每次额外建哈希冻结或重跑无关实验；包部件对比用于实际“只改某页”等要求。
7. 字体声明和实际字重/缺字/换行分开核。实测图源保持纵横比，裁切若改变比较含义须说明。

随包`audit_pptx.py`只读审计所有内部关系及实际页面引用的图表/工作簿/备注，输出不含正文。`inspect_deck.py --requirements`只覆盖清单中的对象；不覆盖所有编辑要求。结构工具成功后仍需按内容和设计看成品。

## 设计检查

按真实页面/段落验收：
- 对象可辨识，操作可定位，条件支路确实交汇，公式与变量靠近相应计算。
- 参考中的局部强调、层级框体、图签、宽/弯/汇聚/展开连线与视线组织得到保留，不退化为一套浅色术语框图。
- 行列比较方向、固定/改变条件、总体与样例清楚，负结果和代价可见。
- 标题/主图对齐，放置后主图、字号和数表可读；不能以缩字号补全量内容。
- 按[成品表达审阅](audience-content.md)从最终文件检查标题、正文、图内字、图注/表格、页脚和备注，覆盖继承/新增页及同义残留。收到纠正后交更新成品，不只给过程报告。
- 制作/权限/工具/用户指令/核验过程只进日志与交付报告；备注保留科研讲述，不能承接正文删下的制作话术。
- 检索命中只给候选，需结合本页和来源语义审读。读出问题须核同批样本是否有新逐图结果，分别写真实类别/方位方法、评价对象、条件/指标/分母，不能以抽象新旧标签代替。
- 仅匹配像素不宣称收益已证；完整负结果、必要学术引用、实验条件与未验证范围保留，不按禁词误删。

## Office与编辑性

任务要求且权限可用时，从最终PPTX真正打开/导出检查字体替代、裁切、公式、图片、图表与箭头。测试实际标题/图内标签、箭头、表格/图表数据或公式时，在另存副本上修改、保存、回读和还原。图形/文字/公式编辑粒度分别记录。

若用户只要求交付、取消某次WPS实测或通道受阻，停止受影响操作，写明“未进行真实Office显示/交互编辑验证”。保留结构、内容和设计检查。不把同源PDF叫WPS渲染，不因未测而把整稿接续冻结。

## 异常诊断与接续

| 情况 | 已形成的处理方式 |
|---|---|
| 解析30秒超时/回执超时 | 先看任务和已有输出；接口超时不等于文件失败。诊断后局部重试，不重复批量重型提交。 |
| 本地提取公式乱码、无独立图片 | 看原页和已有本地渲染，对不清公式回源核；不自行云OCR。 |
| 字体登记缺失或本地化名不匹配 | 查family别名/常规与粗体；缺失列出。允许替代时记录映射并重排，不静默回退。 |
| PptxGenJS富文本挤成一行 | 复核每run字体/字号和breakLine；多行用实际后端的breakLine，不假定字符串换行始终保持。 |
| 原生弯箭头显示回钩 | 看真实流向，不仅看preset名；使用已核曲线/标准箭头尖的适用实现，重新看页面。 |
| SVG含不支持路径/transform/CSS | 保留源，明确不支持项；只迁移已覆盖部分，必要时采用已允许无字图形层＋原生标签，不声称全图可编辑。 |
| 图表数目少于旧记录 | 从页面关系重查实际chart part及工作簿，不按旧文件名漏计。 |
| 自绘预览与Office不同 | 分开记录两种输出；只修具体差异，不用预览替Office作证明。 |
| GUI可读但点击无目标状态变化 | 停止承诺可靠控制，检查能力/错误；不反复让用户切窗口，不脚本绕路。 |
| 缺某个PDF/图片渲染库 | 优先已有预览与当前可用路径，报告受影响能力；未经授权不装依赖。 |
| 图件导出受库规则限制 | 仅暂停导出；继续已有授权文字/结构，申请最小素材范围。 |
| 单页完成、整稿仍旧 | 明确文件身份；风格已确认则推广到完整稿、更新入口后再交，不以单页掩盖整稿缺口。 |
| 目录仍引用旧页码或固定截取章节 | 由实际页序重算章节范围，更新跳转/页内导航和正文/备注引用，不只改目录文字。 |
| 清理制作语言后出现方法事实补造或条件丢失 | 回核来源与评价对象；中性重写或保留必要限定，修实际成品，不用关键词清除率判通过。 |
| 平台缺shell/skill发现/工件交付 | 按platform-contract交给获授权执行者或停依赖步骤；不切preset/审批模式绕过、不启动实跑补证。 |
| 前后研究状态冲突 | 以当前正式事实源核对，只修对应内容；保存依据，不把旧未执行状态写成永久规则。 |

## 停止条件

已交完整版本、必要检查覆盖当前改动、遗留明确且无必须补查的具体失败时停止。不要继续安装、扩展技能、做新实验或追加无依据的全面审查。只封装技能时，允许静态/语法/无写入预检与既有文件只读回归；不得触发生成新PPT的with/without评测。
